When a component needs its own breakpoint

A card can have room for a photo beside its text in the main column and need a stacked layout in the sidebar. CSS container queries let the same component do both.

Maya Chen September 17, 2026

Start with the space the card gets

We first noticed the problem on our journal homepage. The lead story card looked good on a laptop, so we reused it in the sidebar on article pages. At the same browser width, its thumbnail took up nearly half the sidebar, leaving a narrow column for the headline. A headline that fit on two lines in the main feed ran to five lines alongside the photo.

Both cards were following the same viewport breakpoint. Once the browser crossed that threshold, both switched to the side-by-side layout. We wanted the sidebar card to stay stacked for as long as its own column was narrow, even when the rest of the page had plenty of room.

“Start with the headline that barely fits. It will tell you more about the breakpoint than the width of the laptop on your desk.”

Let the card’s wrapper set the breakpoint

Wrap each card in an element with the class story-slot. The wrapper becomes the query container, and the story-card inside it changes layout when the wrapper is wide enough. Give the card two direct children, one for the image and one for the text, so they can sit in separate grid columns.

.story-slot {
  container: story / inline-size;
}

.story-card {
  display: grid;
  gap: 1rem;
}

@container story (min-width: 32rem) {
  .story-card {
    grid-template-columns:
      10rem minmax(0, 1fr);
    align-items: start;
  }
}

Below 32rem, the grid has one implicit column and the image sits above the text. At 32rem, the image column takes 10rem and the text gets the remaining space after the gap. The stacked layout also serves as the fallback where container queries are unsupported.

Test around the threshold

Put two copies of the card on the same page, one in a narrow column and one in a wide column. Drag the divider between them or adjust their widths in the browser inspector. Watching one card switch while the other stays put makes it easy to see whether the query is responding to the intended wrapper.

Check the widths just below and above the threshold with a long headline, a short one, and an image that fails to load. Try the page at 200% zoom as well. In our case, the longest headline still felt cramped when the photo moved beside it, so we raised the threshold until the text could wrap comfortably.

Keep page decisions at the page level

The journal still uses a viewport breakpoint to decide when the main column and sidebar sit side by side. The card’s query handles what happens after it lands in either column. When we added a third placement beneath the article, the card picked up the right layout as soon as it had a wrapper.
