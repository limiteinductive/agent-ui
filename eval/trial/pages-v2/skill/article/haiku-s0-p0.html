Designing Calm Interfaces for Busy Engineers

Most dashboards are loud by default. Here is how we rebuilt ours around restraint, predictable layout, and a handful of rules that any team can adopt this week.

 Mara Okafor Staff engineer · November 18, 2026 · 9 min read

The problem with urgency everywhere

Our internal operations dashboard had grown the way many tools do. Every metric got a color, every change got a badge, and every alert arrived with the same red border. Within a few months, nobody could tell which numbers mattered. People scanned the screen, felt vaguely anxious, and then closed it to go look at the thing they actually needed somewhere else.

The fix was not a redesign in the usual sense. We did not change the brand, swap the component library, or hire a consultant to tell us our palette was wrong. We changed how the page decided what deserved attention, and we wrote those decisions down so they could survive the next round of feature requests.

A dashboard that shouts about everything has quietly stopped communicating anything at all.

— from our design review notes, March

Start with a single resting state

Before adding any emphasis, we defined what the page looks like when nothing is wrong. That resting state became the baseline. Numbers were set in a single neutral ink, labels were muted, and the grid had no color at all. Only deviations from expected ranges were allowed to draw the eye.

This sounds obvious, but it forced an uncomfortable conversation. Several teams had come to rely on their metric being bright red so it would be noticed in standup. We moved those teams to a dedicated status strip at the top of the page, where a single sentence summarizes what is off, and the rest of the grid stayed quiet.

Make layout do the work

Color is the loudest tool in the box, so we reached for layout first. Related metrics sit together in tight groups separated by generous space. Each group has one heading and nothing else competing for attention. When the grid reflows on a narrow phone screen, the groups stack in the same order, which means a person who learned the page on a desktop does not have to relearn it on their commute.

We also stopped putting everything in cards. A card is a strong statement that a thing is separate from its neighbors. Using cards for every value told the reader that every value was equally separate, which is exactly the opposite of what a summary should say.

Measure the reading, not the rendering

Calm is a property of how people read a page, so we tested it that way. We recorded how long it took a new engineer to answer three questions: is the service healthy, what changed in the last hour, and where should I look next. The first version took almost forty seconds on average. After the rework it dropped to under twelve.

Performance mattered too. A calm page that jitters while data loads feels anything but calm. We reserved space for every number before its value arrived, which eliminated layout shift entirely and made the page feel settled the moment it appeared.

A small example

Most of the status logic lives in one function. It takes a metric and its expected range and returns a single state, and the view never makes its own decisions about color. Keeping that logic in one place made it easy to review and easy to change when a threshold turned out to be wrong.

// Returns a single state per metric; the view maps state to ink.
function resolveState(value, { expected, tolerance = 0.1 }) {
  const [low, high] = expected;
  const span = high - low;
  if (value >= low && value <= high) return "nominal";
  const drift = value < low ? (low - value) / span : (value - high) / span;
  return drift <= tolerance ? "watch" : "attention";
}

resolveState(412, { expected: [200, 400] }); // "watch"

The important design choice is the middle state. Without "watch," everything outside the range became an alarm, and people learned to ignore alarms. A mild deviation now reads as a note rather than a siren, and "attention" is reserved for things that genuinely need a response.

What we would tell another team

If you are about to add another color to a page that already has five, stop and ask what question the new color answers. If the answer is "it looks important," that is not enough. Write down the resting state, decide who is allowed to interrupt it, and make the cost of interruption visible in the design itself.

Calm does not mean empty. It means every element on the page has earned its place by changing what someone does next. Everything else can wait, and the page should be honest enough to let it.
