The Quiet Revolution of CSS Container Queries

Components that respond to the space they live in, not the screen they happen to be viewed on.

 Mara Lindqvist November 18, 2026 · 9 min read

For more than a decade, responsive design meant one thing: asking the viewport how wide it was. That worked when pages were a handful of templates. It stops working the moment a card can appear in a sidebar, a modal, a full-width grid, and an email preview, all on the same screen size.

Why viewport queries fall short

A media query answers the question "how big is the window?" But a component rarely cares about the window. It cares about the slot it was dropped into. Teams end up writing variants like .card--narrow and .card--wide, then threading props through every layout to pick the right one.

That coupling is the real cost. Every new placement of a component becomes a negotiation between the component author and the page author.

"The best component is one that doesn't need to be told where it is."

Enter container queries

Container queries let an element ask about the size of its nearest containing ancestor. You declare a container, then write rules against its width. The component adapts on its own, wherever it lands.

.card-wrap {
  container-type: inline-size;
  container-name: card;
}

.card {
  display: grid;
  gap: 1rem;
}

@container card (min-width: 480px) {
  .card {
    grid-template-columns: 160px 1fr;
    align-items: center;
  }
}

Notice what is missing: no class toggles, no JavaScript, no resize observers. The browser does the measuring and the cascade does the rest.

Practical patterns

After migrating a design system of about forty components, a few patterns kept showing up:

  • Wrap, then query. Keep the container element separate from the element you restyle, since a container cannot style itself.
  • Prefer inline-size. Querying height is rarely needed and has layout side effects.
  • Use container units. cqi makes type and spacing scale with the slot.

What to watch out for

Containment is not free. Declaring container-type applies layout and style containment, which can change how children size themselves. Test intrinsic sizing early, especially for elements that relied on shrink-to-fit behavior.

Also resist the urge to query everything. Start with the two or three components that have the most placements, prove the model, and expand from there.

Closing thoughts

Container queries do not replace media queries. Page-level decisions like navigation layout still belong to the viewport. But for components, the shift is profound: design systems can finally ship pieces that are genuinely portable.
